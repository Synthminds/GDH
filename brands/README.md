# Brand packs

A brand pack is the portable copy of one brand's design system. Any agent can read it from disk, with or without a connector. GDH skills look for a pack when they "find the design system first" (kernel rule 2).

## What a pack holds

| File | Holds |
| --- | --- |
| `README.md` | The brand book as usage rules: content fundamentals, visual foundations, iconography, and rules that name tokens. |
| `tokens.json` | Every value, in the Claude Design System token shape. The single source. |
| `tokens.css` | Custom properties for each theme. Generated by `ds.py export`. Do not edit. |
| `DESIGN.md` | Prose and YAML front matter for any coding agent. Generated by `ds.py design-md`. Do not edit. |
| `SOURCE.md` | Where each value came from, the date it was read, and what is INFERRED. |
| `assets/` | Logos, icons and imagery as supplied, with an assets table of source and license. |
| `components/`, `fonts/`, `specimen.html` | Optional: component notes, licensed font files and a specimen page. |

`gdh.py check` requires `README.md` and `tokens.json` in every pack folder present on disk. The full file table and the rules are in [_template/PACK.md](_template/PACK.md).

## The example pack and the template

- [example-harbor-lantern](example-harbor-lantern/README.md) is a finished pack for a fictional brand. Open its `specimen.html` and `sample.html` in a browser to see what a pack produces. Its `SOURCE.md` shows how each choice traces to the subject.
- [_template](_template/README.md) is the starter that `ds.py init` copies. Its values are placeholders, not a brand.

## Make a pack

1. Scaffold it: `python3 kit/skills/design-system/scripts/ds.py init brands/<slug> --name "<Name>"`.
2. Run the `design-system` skill. It reads the brand sources, fills `tokens.json` and `README.md`, and records each value in `SOURCE.md`.
3. Check and generate:

```
DS="python3 kit/skills/design-system/scripts/ds.py"
$DS validate  brands/<slug>/tokens.json
$DS contrast  brands/<slug>/tokens.json
$DS export    brands/<slug>/tokens.json --css brands/<slug>/tokens.css
$DS design-md brands/<slug>/tokens.json --readme brands/<slug>/README.md -o brands/<slug>/DESIGN.md
$DS specimen  brands/<slug>/tokens.json -o brands/<slug>/specimen.html
```

4. Run `python3 scripts/gdh.py check` from the repository root.

A contrast failure in a brand's own value stays exact. Flag it in the token's usage note and in the pack README, and ask the owner. Do not change a brand value to pass a check.

## Private packs

This repository is public. It carries only the example pack and the template.

- The owner's private packs may sit in this folder in a local working copy. `.gitignore` ignores every folder here except `_template/` and `example-harbor-lantern/`, so a new pack is private from the start. Nothing has to be added.
- Never write a private pack's folder name in a tracked file. That includes `.gitignore`. Put an extra local rule in `.git/info/exclude`, which git never commits.
- `gdh.py check` validates every pack present on disk, private or public.
- Keep private facts out of any pack that could become public: no client names, no account ids, no private links.
- To use a private pack in a project, copy it into that project or keep it in a private copy of this repository.
