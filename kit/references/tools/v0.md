# v0 by Vercel

Catalog entry: [v0.json](../../catalogs/tools/v0.json). Source: https://v0.app/docs

Terms in this card. A chat is one v0 project: a conversation with the model plus the generated files. A version is one generation result inside a chat. A task is a point where the chat waits for an answer. Design Mode is an edit request scoped to named elements.

Research could not sign in to v0. Every line in this card comes from the tool schemas and the server instructions. Treat each "Default:" line as an assumption to confirm in the first live session.

## What it makes

- React web apps, dashboards and data views as source files, with a live preview URL.
- An editable code project from a Claude Design HTML export.
- Edits by prompt, or edits scoped to an element: style, text, order, removal, font.
- Typography and color applied in code. It does not make a token file on its own.
- A Vercel deployment of the chat.
- Optional raster images inside a generation.
- It makes no logo, brand identity, illustration, 3D model or video.

## Connection and auth

- The connector signs in with the user's v0 account.
- The sign-in can lapse while the server stays connected. All tools load, and each call answers that the connection must be reconnected.
- Only the user can reconnect, in the host's connector settings. Ask for that. Do not retry.
- Preflight: call `usage_getSummary`. It proves the sign-in and returns the credit use.
- `securityChecks_create` needs a user API key.
- `credentialAccess` gives the chat sandbox access to GitHub, Vercel and shared npm credentials. It is off by default.
- `credentialAccess` and screenshot URLs do not work for Vercel OIDC principals.

## Cost model

- v0 is credit based. No tool description states a price.
- Default: treat every call that runs the model as a spend call: `chats_create`, `chats_createAsync`, `messages_send`, `messages_sendAsync`, `messages_resolve`, `import-claude-design-from-url`, `securityChecks_create`.
- Default: the model tier and `imageGenerations: true` (up to 5 images for one version) raise the cost.
- Default: these calls are free: `chats_list`, `chats_get`, `chats_getFiles`, `chats_getPreview`, `chats_getUrl`, `messages_list`, `messages_get` and the usage tools.
- Default: file-seeded creates that do not prompt the model are free: `chats_createFromFiles`, `chats_createFromZip`, `chats_updateFiles`.
- `chats_deploy` creates a Vercel deployment and, when needed, a Vercel project. That uses the Vercel plan.
- Live quote: no tool quotes one call. `usage_getSummary` returns the credit use for the active billing scope. `usage_getActivity` and `usage_listEvents` give detail.
- Measure the first run: read `usage_getSummary` before and after one generation. Record the difference in the decision record.
- GATE: before a model call, show the usage summary and the chosen model tier. Get a yes. Call once.

## Call order

1. Call `usage_getSummary`. On a reconnect answer, stop and ask the user to reconnect.
2. Choose one entry point: a prompt, files, a zip URL, a GitHub repository, a template id, a Vercel project or a Claude Design URL.
3. Create or import the chat. Prefer the async variant for a long generation.
4. After an async create, poll the assistant message until `finishReason` is not null.
5. Poll `chats_getPreview` until it is not null.
6. Call `chats_getUrl` with the chat id and share that URL. Never build a chat URL by hand.
7. When the chat stops on a task, answer it with `messages_resolve`. A task is a plan review, a choice question, a permission request or an integration install.
8. Iterate with `messages_send` or `messages_sendAsync`. Call `chats_duplicate` before a risky change.
9. Call `chats_getFiles` and write the files into the repository.
10. GATE: call `chats_deploy` only on request.
11. Inspect projects, deployment status and logs with the Vercel connector or the Vercel CLI, not with v0.

## Key tools

| Tool | Use it when |
|---|---|
| `usage_getSummary` | Before a generation run, to read the credit use. |
| `chats_create`, `chats_createAsync` | You generate an app from a prompt. Attach references by URL, data URI or inline text. Set `systemPrompt` for stack rules. Attach up to 3 `skills`. |
| `import-claude-design-from-url` | A Claude Design HTML export must become a new private chat. |
| `chats_createFromFiles`, `chats_createFromZip`, `chats_createFromRepo` | Existing code must seed the chat, so that v0 edits and does not invent. Up to 100 inline files. |
| `chats_createFromTemplate` | You start from a v0 template by id. |
| `messages_send`, `messages_sendAsync` | You iterate with a plain prompt or with `designMode.edits`. |
| `messages_resolve` | The chat waits on a plan approval, a question or a permission. |
| `chats_getPreview` | The user needs the live preview URL for review. |
| `chats_getFiles` | The generated source must enter the local repository. |
| `chats_updateFiles` | Local edits must go back, so that v0 continues from the current code. |
| `chats_duplicate` | You fork a direction to keep variants side by side. |
| `chats_deploy` | The user asks to ship the chat to Vercel. |

Design Mode edit types, from the `messages_send` schema:

- `style`: a camelCase CSS property with `from` and `to`, on an element found by `selectorPath` and `tagName`. Use `textContent` to replace text.
- `deleteElement`, `move` (before, after or inside) and `fontInjection` (add a font).
- An optional `screenshot` with an anchor element gives visual context. One call takes up to 100 edits.

## Inputs

- A working sign-in.
- The brief, plus references: screenshots, brand tokens, a design-system skill or the Claude Design export URL.
- A choice of model tier, and whether image generation is on. Read the allowed values in the `chats_create` schema.
- A privacy level: `private`, `team`, `team-edit`, `unlisted` or `public`.
- Consent before `credentialAccess` is granted.
- Stack rules for the target repository, passed in `systemPrompt`.

## Outputs and how to bring them into a project

- Source files from `chats_getFiles`. Write them into the repository, or commit through a chat linked to GitHub.
- Default: expect a Next.js App Router project. The schema examples use `app/page.tsx`. No schema states the stack.
- A preview URL from `chats_getPreview`. A chat URL from `chats_getUrl`. A deployment through `chats_deploy`.
- Replace generated colors, sizes and fonts with the project tokens before the code merges.
- Review the rendered preview at each breakpoint and theme. A generated page is a draft, not a verified deliverable.

## Handoffs

- From a Claude Design canvas: `import-claude-design-from-url` with `url` and `title`. The URL is a Claude-hosted HTTPS link, valid for about 1 hour.
- Default: no direct tool takes a Figma or Framer design. Attach a screenshot or exported HTML.
- Default: component code from a component catalog enters as inline text attachments or as seed files.
- To Vercel: `chats_deploy` and `chats_createVercelProject`. From Vercel: `chats_createFromVercelProject` with the project id.
- To a design file: take the files or a static HTML render and use a code-to-design tool.
- To the coding harness: the files from `chats_getFiles` plus the decisions in `design/handoff.md`.

## Limits and failure modes

1. The Claude Design import uploads the fetched HTML to a public Vercel Blob before generation. The chat is private; the blob is not.
2. GATE: never import a confidential design without the user's explicit yes.
3. Design Mode changes are model generated. They are not exact DOM patches. They use a model that v0 picks. Verify each result.
4. Sync creates and sends block until the model finishes. Use the async variants for long work.
5. An AI Gateway model id must support tool calling and zero data retention and must pass team policy. Otherwise the call is rejected.
6. A `public` or `unlisted` privacy level exposes the chat. Use `private` unless the user chooses another level.
7. The preview host tools (`settings_*PreviewHosts`) manage where a preview can be embedded. Their effect was not verified.
8. A lapsed sign-in looks like a healthy server. Run the preflight before you plan work around v0.
9. v0 writes application code. Do not ask it for a logo, an illustration, a 3D model or a video.
10. Generated layouts drift toward common patterns. Run the tell scan on choices the design system does not prescribe.
11. Never retry a spend call after a timeout. Read the chat state with `chats_get` and `messages_list` first.

## Best for

1. A working React dashboard or internal tool from a brief plus brand tokens, with a preview URL for review.
2. Turning a Claude Design canvas into an editable code project, then iterating by prompt.
3. Tight element-level refinement rounds with the user through Design Mode edits: spacing, color, copy, font.

## Wrong for

Logo design, brand identity, illustration, 3D models or video. v0 writes application code. Use a vector or media generation tool for those assets.
