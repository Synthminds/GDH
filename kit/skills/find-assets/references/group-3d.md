# Group: 3D

Catalog group `3d`: 3D models, HDRIs, materials and the web 3D toolchain. Read this file at step 6 of `find-assets` when the need is a model, an environment, a material or a 3D library.

How to read this file. An id is a catalog id. An id marked `*` has `verifiedOn` null: read its license before use. Every pick is a default from desk research. Evidence: UNTESTED in a build. License notes are DOCUMENTED on the catalog date, except where marked `*`.

Scene design, budgets and delivery belong to `three-d`. A model that does not exist yet is `generate-media`, with the spend gate. This file covers sourcing and license.

## Decision rules

1. Download the file. Do not build the product on a source's live API unless the user accepts the credit duty.
2. Self-host every HDRI and texture. A helper preset that loads from a remote host is a hotlink.
3. Optimize before you record. The manifest hash is the hash of the file that ships.
4. Keep the source file under `design/assets/` when the license allows, and record it too.
5. For a per-model library, read the model page. Answer question 9: is the uploader the maker?
6. A model of a real product, a character or a branded object carries rights the license cannot grant. Question 8.
7. A credit-required model needs the credit string exactly as the source gives it.
8. Prefer a public domain model from a curated library over an attribution model from an upload site at equal fit.
9. A stylised kit sets the look of the whole scene. Use one kit, or none.
10. Re-light and re-material a sourced model with the scene's own tokens. A model at its default material looks like its source.
11. Default: budgets come from `three-d`. Measure on the target device. No number in the catalog is a gate.

## License traps

- Public domain assets beside protected site content: the library's own text, logos and renders are not public domain.
- Two statements on one site (`quaternius*`): the stricter one governs until you read the file in the pack.
- A model library's license filter can be wrong for one item. Read the item page.
- Non-commercial and no-derivatives models are common in upload libraries. Both block client work.
- A model generated by a tool has that tool's output terms. Record them as `--origin generated`.
- A runtime package with no declared license (`spline*`) is unknown, not free.

## Failure patterns

| Name | Sign | Fix |
| --- | --- | --- |
| Raw download shipped | A model at its original size and texture resolution in production | Run the optimize step. Record the result. |
| Preset environment | Lighting from a helper preset on a remote host | Download the HDRI, self-host it, record it |
| Test model as hero | A well-known sample model as a brand visual | Replace it |
| Unknown uploader | A model whose page shows no author work | `blocked`. Pick another. |
| Kit clash | Two low-poly kits with different proportions | One kit |
| Lost credit | An attribution model with no credit line | Add the exact string. Run `notices`. |

## Worked choice

The outcomes below are illustrative. They show the reasoning, not verified facts about a source.

Need: a neutral studio environment and a small plant model for a furniture product viewer. Ships in a client product.

- Catalog: `A search <catalog> --group 3d --query "hdri" --commercial --no-attribution`.
- Environment: a studio HDRI from the public domain library. Downloaded at a web resolution, self-hosted, recorded.
- Plant: an upload library has the best match under an attribution license. The uploader's page shows the source files. Question 8: no brand, no product design.
- Decision by the user: accept the credit on a credits page. Verdict `clear with duties`.
- Pipeline: optimize the plant with the model optimizer. Record the optimized file with `--modified` and the note "Compressed and textures resized."
- The furniture model itself is the client's own file: `--origin own`.
